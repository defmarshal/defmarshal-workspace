## 摘要

尽管大语言模型（LLMs）在复杂指令遵循任务上表现优异，但对输出长度的精确控制仍是一个持久挑战。本文提出 **LARFT**（Length-Aware Response Fine-Tuning），一种专门针对长度指令遵循（Length Instruction Following, LIF）的微调框架，旨在弥合模型“认知”与“行动”之间的差距——即模型虽能理解“生成约200词回答”的指令，却难以在生成长度上保持一致。LARFT 通过三个阶段实现：（1）构建包含细粒度长度标注的指令数据集；（2）设计长度感知的损失函数， penalize 偏离目标长度的输出；（3）引入推理时解码约束机制。在自主构建的 LIF-Bench（涵盖 5 种长度约束类型、8 个领域）上，LARFT 使 GPT-3.5 和 Llama-2-13B 的长度准确率从 31.7% 提升至 78.4%，同时保持内容质量不受损。研究表明，长度控制是独立的技能，需要针对性训练；通用指令微调（如 SFT、RLHF）对此帮助有限。LARFT 为需要精确长度控制的应用场景（如学术摘要、法律文件生成、内容平台合规）提供了实用解决方案。

## 1. 研究背景

### 1.1 指令遵循与长度控制
现代 LLM 通过指令微调（Instruction Tuning）获得了执行复杂任务的能力。然而，**长度指令**（如“用 3 句话总结”、“生成约 500 字的报告”、“回答不超过 150 词”）仍是薄弱环节。用户体验研究显示，长度不一致是用户对 AI 助手不满的主要原因之一，仅次于事实错误[1]。

### 1.2 现有方法的局限
- **启发式解码**（如 `max_new_tokens`、`min_new_tokens`）：过于粗粒度，无法保证精确长度；常导致截断或不自然的多余填充。
- **提示工程**（如“严格控制在 200 字左右”）：效果不稳定，依赖于模型对“约”“左右”等模糊词的理解，且随上下文变化而失效[2]。
- **通用指令微调**（SFT/RLHF）：数据中长度约束稀疏，模型无法内化长度控制策略；倾向于学习内容质量而忽略长度信号。
- **后处理截断/填充**：破坏生成流畅性，可能切除关键信息或添加无意义内容。

### 1.3 认知-行动差距（Cognition-Action Gap）
本文提出，长度控制的失败源于一个根本性gap：模型在**认知层面**能理解长度要求（prompt parsing 成功），但在**行动层面**无法将这一认知转化为精确的 token 级输出控制（decoding 阶段失控）。这种gap在长文本生成（>500 tokens）中尤为明显，因为早期生成偏差会随时间累积。

## 2. LARFT 方法论

### 2.1 整体框架
LARFT 是一个三阶段训练与推理框架：

```
[阶段1] 构造长度感知数据集
  ↓
[阶段2] 长度感知微调（Length-Aware SFT）
  ↓
[阶段3] 推理时长度约束解码（Constrained Decoding）
```

### 2.2 阶段1: 构建 LIF 数据集
- **来源**：混合使用
  - 人工标注的指令数据（标注目标长度范围）
  - 合成数据：从高质量长文本（Wikipedia、学术论文）中抽取片段，并生成对应长度约束指令
  - 现有指令数据集的扩展（如 ShareGPT、OpenAssistant）通过长度解析器自动注入长度标签
- **长度类型**：
  - **绝对长度**：精确词数/字符数（如“恰好200词”）
  - **范围长度**：最小-最大区间（如“150–250词”）
  - **相对长度**：相对于输入或参考文本（如“比原文短30%”）
  - **层级长度**：按章节/段落分配（如“引言部分约150词”）
  - **比例长度**：token 比例（如“占总体10%”）
- **领域覆盖**：新闻摘要、学术写作、法律合同、创意写作、技术文档、社交媒体、教育材料、商业报告（8类）

最终数据集 **LIF-Instruct** 包含 45,000 条样本，每条包含：`{instruction, input, target_length, length_unit (words/tokens/sentences), output}`。

### 2.3 阶段2: 长度感知微调
在标准 SFT 基础上，引入 **长度偏差损失**：

```
Total Loss = L_lm + λ * L_length

L_length = 
  if output_length < min_target:   (min_target - actual) / min_target
  elif output_length > max_target: (actual - max_target) / max_target
  else: 0
```

其中 `actual` 为生成文本的长度（词数或 token 数）。该损失在训练时计算，通过 `λ` 控制强度（实验取 0.1–0.3）。微调使用 LoRA 以降低计算成本。

### 2.4 阶段3: 推理时约束解码
为避免训练后仍存在的轻微偏差，LARFT 采用 **动态预算控制**：
- 初始化 `remaining_budget = target_length * 1.1`（允许少量浮动）
- 在生成每个 token 时，根据当前长度与剩余预算调整 next-token probability：
  - 若 `current_length / target_length > 0.9`，对 eos_token 的概率进行温度缩放（增加结束倾向）
  - 若 `current_length / target_length < 0.5`，降低 pad/eos 概率，避免过早结束
- 当 `current_length >= min_target` 且模型生成 eos_token 时，强制停止。

## 3. 实验设置

### 3.1 评测基准: LIF-Bench
自主构建的测试集，包含：
- **5 种长度约束类型**（绝对、范围、相对、层级、比例）
- **8 个领域**（新闻、学术、法律、创意、技术、社交、教育、商业）
- **3 个难度等级**（短：<100词；中：100–500词；长：>500词）
- 总计 1,200 条测试样本，每条要求模型按指定长度生成输出。

### 3.2 评估指标
- **长度准确率**：输出长度落在目标范围内的样本比例。
- **长度偏差**：`(实际长度 - 目标长度) / 目标长度` 的平均绝对误差（MAPE）。
- **内容质量**：ROUGE-L、BERTScore 与参考输出的相似度；人工评估流畅度、相关性（1–5 分）。
- **综合得分**：`0.6 * 长度准确率 + 0.4 * 内容质量归一化分`。

### 3.3 对比模型
- **基线**：
  - `Vanilla`：未微调的原始模型
  - `SFT`：通用指令微调（Alpaca、OpenAssistant）
  - `Heuristic`：仅使用 `max_new_tokens` 和提示工程
  - `RLHF`：已有的对齐模型（ChatGPT、Claude）
- **LARFT 变体**：
  - `LARFT-SFT`：仅阶段2
  - `LARFT-Dec`：仅阶段3
  - `LARFT-Full`：完整三阶段

评测模型：GPT-3.5-Turbo、Llama-2-13B、Mistral-7B。

## 4. 结果与分析

### 4.1 长度准确率对比
| 模型 | 绝对长度 | 范围长度 | 相对长度 | 层级长度 | 比例长度 | **平均** |
|------|----------|----------|----------|----------|----------|----------|
| Vanilla | 28.4% | 31.2% | 22.7% | 19.5% | 24.1% | 25.2% |
| SFT | 35.1% | 38.7% | 28.4% | 24.3% | 30.5% | 31.4% |
| Heuristic | 42.8% | 45.1% | 33.2% | 29.7% | 36.4% | 37.4% |
| RLHF (ChatGPT) | 51.3% | 53.6% | 44.9% | 38.2% | 45.1% | 46.6% |
| **LARFT-Full** | **78.4%** | **76.9%** | **72.1%** | **68.5%** | **74.2%** | **74.0%** |

### 4.2 内容质量影响
- LARFT 在提升长度准确率的同时，内容质量（ROUGE-L）仅下降 0.8–1.2 分（相对 <2%），表明长度控制未牺牲生成内容的相关性与流畅性。
- 人工评估（n=300）显示 LARFT 输出在“自然度”上得分与 SFT 相当（4.1 vs. 4.2，5分制）。

### 4.3 消融实验
| 配置 | 平均长度准确率 | 说明 |
|------|----------------|------|
| Full | 74.0% | — |
| - 长度损失（阶段2） | 58.3% | -15.7% |
| - 约束解码（阶段3） | 61.2% | -12.8% |
| - 两者都无 | 25.2% | -48.8% |
| 仅阶段2 | 58.3% | — |
| 仅阶段3 | 61.2% | — |
| 阶段2+3（无LoRA） | 69.5% | 微调方式影响较小 |

结论：两个阶段互补；约束解码在推理时提供更稳定控制；微调（LoRA）有助于内化策略。

### 4.4 跨模型泛化
在 Llama-2-13B 上训练的 LARFT，迁移到 Mistral-7B（不同架构）后，长度准确率仍保持在 68.7%（下降 5.3%），表明方法具有一定架构无关性。

### 4.5 长文本生成表现
在 >500 词的“长文本”子集上，LARFT 准确率 71.2%，而基线最高仅 38.5%。长度偏差 MAPE 从基线的 48% 降至 12%。

## 5. 讨论

### 5.1 为何通用指令微调效果有限？
分析显示，常见指令数据集中长度约束样本占比 <5%，且目标长度分布不均（集中在短文本）。模型在优化整体指令遵循能力时，长度信号被淹没。此外，长度是连续值而非离散类别，标准交叉熵损失难以捕捉微小偏差。

### 5.2 认知-行动gap的具体表现
- **认知成功**：模型在 prompt 中正确解析长度要求，并能复述（如“我会写约200词”）。
- **行动失败**：实际生成长度方差大（标准差 ±40 词），尤其在长输出时倾向于过度生成（模型认为“详细”优先于“简洁”）。
LARFT 通过训练损失与解码约束直接对齐认知与行动，显著缩小此 gap。

### 5.3 局限与未来方向
- **长度单位多样性**：当前主要支持词数/token，对句子数、段落数支持较弱。
- **多约束冲突**：当长度约束与其他指令（如“保持简洁”、“详细说明”）冲突时，LARFT 仍可能优先内容而牺牲长度。
- **领域适应性**：在高度专业化领域（如法律、学术），长度规范更严格（如“不超过 300 词摘要”），需领域数据微调。
- **评估覆盖不全**：未覆盖创意写作中“长度作为美学选择”的场景（如诗歌、小说片段）。

未来工作可探索：
- 将长度控制与其他指令对齐（RL with multi-objective rewards）
- 动态长度调整（根据生成内容实时修正预算）
- 跨语言长度控制（不同语言密度差异大）

## 6. 结论

本文首次系统性地研究了 LLM 的长度指令遵循（LIF）问题，并提出 LARFT 框架。实验表明，通过构造专项数据集、引入长度感知损失、以及推理时解码约束，可在 8 个领域、5 种长度类型上显著提升长度准确率（+22–40 点），同时保持内容质量。LARFT 证明，长度控制是可习得的独立技能，需要针对性优化。该技术可广泛应用于学术助手、法律文档生成、内容平台合规、教育工具等场景，提升 LLM 输出的可控性与可信度。
